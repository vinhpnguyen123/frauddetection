## Dev decision recorded before the test sanity run

The M4-S4 dev remeasurement is complete. Retain MiniLM and the planned rerank stage
(locked D7); use top-20 for the future answer path rather than top-50. There is no clear
quality improvement from reranking on this dev set (confidence intervals overlap
heavily); this preserves the locked architecture rather than claiming a measured win.
Top-50 adds latency without a clear quality benefit. No retrieval parameter, chunking,
or label changes are made in response to these results. The single test sanity config
remains `hybrid_raw`, fixed before its results. Parent expansion and `final_k` remain M5-S2.

Timings are machine observations under substantial existing swap, not a clean-machine
latency benchmark. The new run does not rehabilitate the historical bge top-50 timings;
those remain invalid and are not reused as comparative latency evidence.

## Held-out set

`datasets/test.jsonl` contains 30 draft questions: 20 real answerable questions scoped to
the FFIEC documents, 4 synthetic answerable questions, and 6 refusal cases. The answerable
questions comprise 10 identifier, 10 concept, and 4 multi-hop items. Every fictional tenant
appears. Public and synthetic items must be reported separately.

Queries were drafted before labels were found by reading/searching PDF text, without
running a retriever. Unsupported premises in the initial synthetic query draft were
corrected during labeling, before any retrieval run. Labeling durations were not recorded.
Codex drafted the set; it has not been human-reviewed. `test.meta.json` records that
status and the dataset hash. The existing dev declaration records the previously
documented Claude draft and Vinh review; dev labels have not changed.

This is a question holdout over the same corpus, not a document holdout. The public
questions focus on FFIEC banking operations; they cannot establish general performance
across all source families. Own-tenant questions and wrong-tenant refusal cases
intentionally share policy topics to check isolation. Retrieval evaluation does not
measure refusal correctness; that requires the later generation pipeline.

Read the questions, quotations, and ambiguity notes before recording a human review.
Confirm relevance and completeness across the requested sources, not just that the
anchor text exists. If labels change, update the hash and reset the review declaration
until the changed labels have been reviewed.
